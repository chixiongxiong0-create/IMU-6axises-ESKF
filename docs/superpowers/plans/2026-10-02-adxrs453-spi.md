# Three-channel ADXRS453 SPI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 实现三颗 ADXRS453 的并行 SPI 采集，并用用户提供的 Vivado 验证协议和时序。

**Architecture:** 单个 32 位 SPI 发送引擎配三路接收器；顶层负责 CHK 启动检查、485 Hz 节拍、A/B 交换配对和原子帧发布。独立行为模型模拟器件锁存、响应流水线与故障注入。

**Tech Stack:** 可综合 Verilog-2001；SystemVerilog testbench；PowerShell；Vivado 2025.1 xvlog/xelab/xsim。

**Spec:** `docs/superpowers/specs/2026-10-02-adxrs453-spi-design.md`（已获用户批准）。协议依据为本地 `ADXRS453.pdf` Rev. B 第 14–23 页。

## Global Constraints

- 默认 CLK_HZ=100000000，SPI_HZ=5000000，SAMPLE_HZ=485。
- 共用 SCLK/MOSI，三路独立 MISO 和同波形 CS_N；Mode 0，MSB first，每次恰好 32 个时钟。
- 全部 RTL 使用 clk 单时钟域；rst_n 低有效，外部负责同步释放。
- SPI 半周期向上取整；CS 提前、保持至少一个半周期，CS 高至少 200 ns。
- 命令全字奇校验；响应高 16 位及全字奇校验；正常 ST=01、故障[7:1]=0、SQ 匹配。
- 启动等待至少 100/50/50 ms；失败器件不阻止其它通道采集。
- 每节拍两次交换，仅 B 响应发布，时间戳对应 A 的 CS 下降沿。
- frame_valid 为完成脉冲，gyro_valid 分路表示协议有效；不声明内部 MEMS freshness。
- 不修改现有 C99 算法或用户已有改动；不增加 AXI、温度或加速度计采集。
- Vivado 根目录默认 `D:/Xilinx/2025.1/Vivado`；不安装工具，不假定 FPGA part 或板级引脚。

## Review Focus

1. 请求紧邻 done 或在 busy 中到来：不重入、不丢失最后接收位；任务 1 检查。
2. 非整除 SPI 分频：实际频率不得超过指定值；任务 1 检查 100 MHz/6 MHz。
3. FPGA 单独复位但器件仍供电：不强制首响应为 0x00000001；任务 2 检查。
4. 一路启动失败且运行时返回正常字：不得恢复为有效，另两路继续工作；任务 2 检查。
5. 仿真断言失败但 xsim 返回成功进程码：脚本必须检查完成标记和失败输出；任务 3 检查。

**Interfaces:**
- `spi_master_3ch #(CLK_HZ, SPI_HZ, CS_HIGH_NS=200)`。
- 输入 `clk, rst_n, start, tx_word[31:0], miso[2:0]`。
- 输出 `sclk, mosi, cs_n[2:0], busy, done, rx0[31:0], rx1[31:0], rx2[31:0]`。
- 脚本参数 `VivadoRoot`、`Suite`（spi/acq/invalid/all）、`BuildDir`；默认执行 all。

- [x] 编写 testbench：独立从 MOSI 重构发送字，驱动三路不同的返回字；逐次验证 32 上升沿、32 下降沿、CS=000/111、MSB first、最后一位不丢失、done 单脉冲和接收结果保持。
- [x] 加入时间断言：默认高低各 100 ns，MOSI 建立 >=37 ns、保持 >=49 ns，CS 提前及保持 >=100 ns，高电平间隔 >=200 ns；再测试 SPI_HZ=6000000 时实际半周期为 90 ns。
- [x] 编写仿真脚本，按 xvlog（RTL 不加 -sv）、xvlog -sv（testbench）、xelab、xsim 顺序运行；保存日志和波形配置，设置 watchdog，完成标记 `PASS: tb_spi_master_3ch`。

- [x] 实现引擎：空闲接受 start，设置首位和 CS；半周期使能控制沿，最后下降沿之后保持再撤销 CS；强制执行 CS 高间隔，不接受 busy 请求。处理复位中止。

## Task 2: ADXRS453 启动与采集控制器

**Files:** 创建 `rtl/adxrs453_acq.v`、`tests/rtl/adxrs453_model.sv`、`tests/rtl/tb_adxrs453_acq.sv`；扩展仿真脚本 acq suite。

**Interfaces:**
- 顶层参数 `CLK_HZ, SPI_HZ, SAMPLE_HZ`，SPI 间隔采用任务 1 的默认 200 ns。
- 输入 `clk, rst_n, miso[2:0]`；输出 `sclk, mosi, cs_n[2:0]`。
- 输出 `signed gyro0/1/2[15:0], raw0/1/2[31:0], timestamp_cycles[63:0], frame_seq[2:0], frame_valid, gyro_valid[2:0], err0/1/2[4:0], startup_done, startup_ok[2:0], overrun`。
- err 位 0–4 分别为高半字奇校验、全字奇校验、SQ、ST、故障错误。
- 行为模型端口为 CS/SCLK/MOSI/MISO，以及测试控制的 16 位数据、响应翻转掩码、SQ/ST 覆盖和七位故障值；覆盖开关独立，避免用合法数据值作为哨兵。

- [x] 建立独立模型：CS 下降沿保存角速度与 CHK 故障状态；当前交换发送上一命令的响应，32 位命令完整收取后才更新响应队列；上电首次响应为 0x00000001。CHK 根据仿真时间在 50 ms 内置故障并延迟消退，故障保持到读取。
- [x] 模型按手册表 9/10 单独构造、校验命令及响应；不引用 DUT 函数。重构命令验证 CHK 序列及 SQ 编码 bit28/31/30，故障位为[7:1]、ST 为[27:26]、角速度为[25:10]。
- [x] 编写默认 100 MHz 全时长启动测试：检查首命令 >=100 ms，后两段等待各 >=50 ms，两次 ST=10 且故障全置位的响应，以及恢复 ST=01；启动结束前 frame_valid 始终为零。
- [x] 运行 `powershell -NoProfile -File tests/rtl/run_vivado.ps1 -Suite acq`，确认缺少顶层时预期失败。
- [x] 实现启动 FSM：100 ms 等待→CHK 交换→50 ms 等待→清 CHK 交换→50 ms 等待→两次故障报告检查→恢复检查；按通道累计 startup_ok，并在结束时置 startup_done。
- [x] 实现相位累加器与 A/B 交换调度。64 位计数器自由运行，A 实际 CS 下降沿捕获时间戳，B 完成时统一发布。SQ 按节拍模 8 前进；忙时丢弃新节拍并锁存 overrun。
- [x] 实现奇校验、SQ、ST、故障检查及原始二补码输出；gyro_valid 还需 startup_ok。无效帧依然发布本次数据，所有输出在两次 frame_valid 之间保持。
- [x] 增加正常三路不同数据及 +80/-80/0/32767/-32768、至少 16 帧 SQ 回绕、B 响应配对和 A 时间戳断言。测试模型在 A/B 之间改变数据，以区分两次锁存。
- [x] 增加错误注入：高半字奇校验、仅全字奇校验、错 SQ、ST=00/10/11、每种故障及 MISO 卡高/卡低；验证坏通道有效位清零、其它通道仍有效。高半字校验注入同时翻转低半字位，使全字校验仍通过，以区分两个检查。
- [x] 检查 485 Hz 节拍间隔 206185/206186 周期，并以累加器余数或足够帧数证明累计误差小于一周期；时间戳保持 A 的参考时刻。
- [x] 覆盖 FPGA 单独复位、启动失败通道继续返回健康字、交换中复位；使用一次可控忙状态延长验证 overrun 不覆盖当前帧，释放后继续采集。
- [x] 运行 acq suite，要求 `PASS: tb_adxrs453_acq` 且无断言或超时；只提交本任务文件，提交说明 `feat: acquire ADXRS453 frames with startup diagnostics`。
