# 三颗 ADXRS453 并行 SPI 采集设计

日期：2026-10-02。状态：用户已批准，2026-10-03 实施；交付和验证见 docs/adxrs453-spi.md。

## 目标与已确认条件

为本仓库 Zynq IMU 系统提供可综合 Verilog-2001 采集模块。用户已确认三颗
ADXRS453 共用 SCLK、MOSI，分别连接三路 MISO；系统时钟暂按 100 MHz。
三个独立 CS 输出使用相同波形。所有内部逻辑只使用系统时钟，SPI 时钟作为
输出信号由时钟使能驱动，不作为内部逻辑时钟。

默认以 485 Hz 读取三路原始角速度。交付 RTL、仿真模型、testbench、Vivado
批处理仿真脚本和中文说明。首版不包含 AXI、温度读取、ADXL355 采集、
角速度单位换算或姿态算法。通道 0/1/2 的机体系轴映射由接入方确定。

## 方案选择

采用共用发送移位寄存器和三路接收移位寄存器，并行交换 32 位数据。
此方案符合已确认接线，且三路寄存器锁存时刻一致。

每个节拍采用 A、B 两次交换，B 返回 A 的锁存数据，可以在当前节拍内发布。
每节拍仅交换一次虽然更省带宽，但需要把上一周期的时间戳和其它传感器数据
一起延迟配对；因此本设计采用两次交换。三套独立 SPI 引擎不适用于目前接线。

## SPI 时序与参数

默认 CLK_HZ=100000000，SPI_HZ=5000000，SAMPLE_HZ=485。
SPI 半周期取 ceil(CLK_HZ/(2*SPI_HZ)) 个系统周期，因此实际 SPI 频率不高于
指定值；默认半周期 10 个系统周期，即 100 ns。

CS 下降时 MOSI 放置最高位；至少等待一个半周期再产生第一个上升沿。
上升沿采样三路 MISO，下降沿切换下一位 MOSI。第 32 个下降沿之后再保持
CS 低至少一个半周期，随后 CS 变高。两次交换间 CS 高至少 200 ns，且参数
换算采用向上取整。最后一位之后不得产生第 33 个时钟。

MISO 是与受控 SCLK 相关的返回数据，按 SPI 时序在系统时钟域采样；不能
任意加入会改变位关联的两级同步器。接入说明给出引脚、输入/输出延迟和板级
时序约束的要求；未确定器件封装、引脚和走线延迟前不提供假定的板级 XDC。

参数必须满足正数、SPI_HZ<=8080000、半周期至少满足 MOSI 时序要求，
采集周期足以容纳两次交换。非法配置在仿真中明确报错。

## 模块和端口

`rtl/spi_master_3ch.v`：固定 32 位交换引擎。

- 输入 clk、rst_n、start、tx_word[31:0]、miso[2:0]。
- 输出 sclk、mosi、cs_n[2:0]、busy、done、rx0/1/2[31:0]。
- start 为单周期请求，仅空闲时接受；done 为完成后的单周期脉冲。
- 复位中和空闲时 SCLK=0，CS_N=111，MOSI=0；接收结果保持到下一次完成。

`rtl/adxrs453_acq.v`：顶层启动、调度、协议检查和帧发布。

- 输入 clk、rst_n、miso[2:0]；rst_n 为低有效复位，释放须同步到 clk。
- 输出 sclk、mosi、cs_n[2:0]。
- 输出 signed gyro0/1/2[15:0] 和 raw0/1/2[31:0]。
- 输出 timestamp_cycles[63:0]、frame_seq[2:0]、frame_valid、gyro_valid[2:0]。
- 输出 err0/1/2[4:0]、startup_done、startup_ok[2:0]、overrun。

err 每路位定义：bit0 高 16 位奇校验错误，bit1 全字奇校验错误，bit2 序号
不匹配，bit3 ST 非 01，bit4 原始故障位[7:1]非零。有效标志还受 startup_ok
约束；通过 raw 可查看具体故障字段。err、raw、gyro 和时间戳在 frame_valid
时一起更新，即使某路无效也保留本次实际数据，不替换成旧的有效角速度。

frame_valid 仅表示该帧交换、检查完成，不保证三路全部健康。数据输出保持到
下次发布。消费者只在 frame_valid 时读取，并分别检查 gyro_valid。

## 命令与响应

正常 Sensor Data 命令的 SQ[2:0] 编码为 bit28=SQ2、bit31=SQ1、bit30=SQ0；
bit29=1、bit1=CHK=0、其余保留位为零，bit0 补齐全 32 位奇校验。
序号按采集节拍递增，模 8 回绕。A 和 B 使用相同序号；B 的返回必须与 A
的序号配对，A 返回的上一条命令响应不作为当前帧发布。

正常响应 SQ=response[31:29]，ST=response[27:26]，角速度=response[25:10]，
故障=response[7:1]。要求 ^response[31:16]=1、^response[31:0]=1、
SQ 匹配、ST=01、故障为零。读写错误响应的 ST=11 被判为无效，保留原始字。

## 启动流程

从 FPGA 复位释放开始保守等待 100 ms；接入方保证此时传感器供电已有效。

1. 发送 CHK 命令 0x20000003；丢弃响应，冷启动时通常为 0x00000001。
   FPGA 单独复位时器件不一定再次返回该初始字，因此不强制要求它相等。
2. 交换结束后等待至少 50 ms，发送 0x20000000 清除 CHK；丢弃此次响应。
3. 交换结束后等待至少 50 ms，再发送正常命令，检查响应为 ST=10 且七个
   故障位全部为 1，并检查两个奇校验。
4. 等待 CS 高电平间隔后再发正常命令；同样检查第二个故障报告响应。
5. 再发正常命令，要求 ST=01、SQ=000、故障为零且奇校验正确。

仅两次故障报告和恢复检查均通过的器件置 startup_ok。startup_done 表示
流程完成，允许某一路失败而其余器件继续采集。startup_ok 保持到复位，
失败器件的运行帧仍输出诊断字但不置 gyro_valid。启动期间不产生 frame_valid。
不自动反复触发 CHK，重新执行启动流程需复位。

## 采集节拍与时间戳

启动结束时清零相位累加器；每个系统周期累加 SAMPLE_HZ，达到 CLK_HZ
时减去 CLK_HZ 并产生一次节拍。100 MHz/485 Hz 下间隔为 206185 或
206186 个系统周期；平均频率为 485 Hz，不使用截断整数分频。

在 A 交换真正开始、三路 CS 下降的系统时钟沿保存自由运行 64 位计数器。
计数从复位释放后开始，100 MHz 下每计数 10 ns。B 交换完成后发布该 A
时间戳，而不是 B 的锁存时间戳。时间戳是主机寄存器锁存参考，不证明三个
MEMS 的内部物理采样同步，也不用于判断新鲜度。相同数值不等于重复采样，
frame_valid 和 gyro_valid 也不声明已知的 MEMS freshness。

运行中若新节拍到来时上一帧仍忙，则丢弃新请求、不覆盖当前帧，overrun
置位并保持到复位。frame_seq 仍按节拍前进，以便观察丢失的主机采集帧。

## 仿真与验收

使用用户提供的 `D:/Xilinx/2025.1/Vivado` 下 xvlog、xelab、xsim。
脚本默认使用该位置，也允许传入其它 Vivado 路径；产物写入独立 build 目录。
RTL 以 Verilog-2001 编译，testbench 可使用 SystemVerilog。

测试包含：

- 默认 100 MHz/5 MHz 下精确 32 时钟，Mode 0 边沿、MSB first、CS 三路对齐、
  MOSI 建立保持、CS 提前保持和两次交换间隔。
- 完整默认 100/50/50 ms 启动等待及 CHK 流水线；启动失败只阻止对应器件有效。
- 三路不同数据、正负数和二补码边界；A 锁存值与 B 响应正确配对，时间戳
  对齐 A 的 CS 下降沿；模 8 序号回绕。
- 分别注入高半字校验错误、仅全字校验错误、错误序号、ST=00/10/11、故障
  位，以及 MISO 卡高/卡低，确保无效数据不会被标记有效。
- 分频向上取整、485 Hz 两种周期长度和累计节拍误差小于一个系统周期。
- 空闲和传输中复位、复位后重新启动；输出恢复安全状态。
- 强制忙状态下的节拍丢弃和 overrun 行为；非法参数明确拒绝。
- Vivado 编译、展开、仿真成功，testbench 报告断言通过且无超时。

仿真模型不能代替实板验证。最终报告明确区分 RTL 仿真和目标器件综合、
布线时序、板级电气及逻辑分析仪验证；未指定完整 FPGA part 时不声明上板通过。
